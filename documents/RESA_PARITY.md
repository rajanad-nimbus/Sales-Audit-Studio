# ReSA 15.0.1 workflow parity

This map translates the supplied [Oracle Retail Sales Audit User Guide, Release 15.0.1](resa-1501-ug.pdf), into reviewable ZeTSA capabilities. “Covered” means a corresponding workflow is present in the current code; it does not claim production integration or complete end-to-end validation. The guide describes the reference workflow, while ZeTSA keeps external identity, immutable audit history, and independent financial approvals as platform controls.

## Work to close the largest gaps

Agent Activity uses one server-side filter predicate for its cursor-paged browse and bounded full CSV export, so searches and actor/attention filters apply to the complete audit stream rather than only the rows already loaded in the browser.

1. **Restore a green regression baseline.** The last broad backend run reported 46 failures, 1,137 passes, and 14 skips. Triage those failures before using the suite as evidence of parity. PostgreSQL concurrency tests also require a disposable configured database.
2. **Finish identity and location administration.** Define the employee lifecycle between Ontology Studio and ZeTSA, and validate how retailers govern store location traits and assignment changes.
3. **Complete common workspace affordances.** Expand contextual help to a full searchable guide, extend visible-row CSV export to remaining worklists, and add all-matching server exports to remaining queues; keep the current responsive UI and accessibility preferences.
4. **Validate production integrations.** Connect real POS/OMS, bank, and downstream retail/GL systems using their actual contracts; synthetic feeds and a development sink do not prove production interoperability.
5. **Run end-to-end lifecycle reviews.** Verify import → audit → correction → re-total/sign-off → close → export/acknowledgement, plus ACH and voucher aging/escheat, using a disposable PostgreSQL environment and rendered UI flows.
6. **Validate policy promotion operationally.** Reconciliation tolerance and duplicate-detection settings now support versioned JSON export, preview, stale-preview checks, finance-only apply, and reasoned audit events. Verify the promotion flow with representative policies in a disposable environment.

This is a living traceability map. Update each row when implementation or integration evidence changes; do not mark a capability covered solely because a route or screen name exists.
